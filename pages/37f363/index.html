# 基础知识

Android Debug Bridge (adb) 是一个功能强大的命令行工具，允许您与 Android 设备进行通信。adb 命令可以执行各种设备操作，如安装和调试应用程序。adb 提供了对 Unix shell 的访问，您可以在设备上运行各种命令。

# 核心概念

  • adb client: 在开发机器上运行的客户端程序
  • adb server: 在开发机器上运行的后台进程，管理客户端与设备的通信
  • adbd: 在 Android 设备上运行的守护进程

# 运行原理

adb 的运行原理是 PC 端的 adb server 与手机端的守护进程 adbd 建立连接，然后 PC 端的 adb client 通过 adb server 转发命令，adbd 接收命令后解析运行。

# 连接流程
adb client → adb server → adbd (设备端)

# 获取fd

# 查询指定包名的应用文件描述符 (FD) 数量
adb shell "MAIN_PID=\$(pidof <package> | awk '{print \$1}'); run-as <package> ls -l /proc/\$MAIN_PID/fd" | wc -l
# shell function 实现
get_fd_count() {
    local package=$1
    if [ -z "$package" ]; then
        echo "使用方法: get_fd_count <package_name>"
        return 1
    fi

    # 执行命令
    adb shell "MAIN_PID=\$(pidof $package | awk '{print \$1}'); run-as $package ls -l /proc/\$MAIN_PID/fd" | wc -l
}

# 测试自动化脚本

#!/bin/bash
# 性能测试脚本

PACKAGE_NAME="com.example.app"
TEST_DURATION=60  # 测试时长（秒）

echo "开始性能测试..."

# 启动应用
adb shell am start -n "$PACKAGE_NAME/.MainActivity"

# 开始性能监控
adb shell am profile start "$PACKAGE_NAME" /sdcard/performance.trace

# 执行测试操作
for i in {1..10}; do
    echo "执行第 $i 轮测试..."
    adb shell input swipe 300 1000 300 500
    sleep 2
    adb shell input tap 500 500
    sleep 1
done

# 停止性能监控
adb shell am profile stop "$PACKAGE_NAME"

# 拉取性能数据
adb pull /sdcard/performance.trace ./performance_$(date +%Y%m%d_%H%M%S).trace

echo "性能测试完成"

# 资源监控脚本

#!/bin/bash
# 资源监控脚本

monitor_resources() {
    while true; do
        echo "=== $(date) ==="
        echo "CPU使用率:"
        adb shell top -n 1 | head -10
        echo ""
        echo "内存使用:"
        adb shell cat /proc/meminfo | head -5
        echo ""
        echo "存储使用:"
        adb shell df /sdcard
        echo "=================="
        sleep 30
    done
}

# 7. 实用技能

# 7.1 forward/revese 端口转发

adb forward 是 Android 开发中非常强大的一个“内网穿透”工具。它的本质是 端口转发：将你 电脑（Host） 上的某个端口，映射到 手机（Android） 内部的某个端口。Android 端口转发（Forward & Reverse） 的实操与避坑全指南

  1. adb forward (正向转发)

    方向： 电脑 (Host) -> 手机 (Android) 本质： 将电脑上的某个端口映射到手机内部的某个端口。当电脑访问自己的这个端口时，请求会被转发到手机。

  2. adb reverse (反向代理)

    方向： 手机 (Android) -> 电脑 (Host) 本质： 将手机上的某个端口映射到电脑的某个端口。当手机访问自己的 localhost 端口时，请求会被转发到电脑。

# 7.1.1 adb forward：电脑访问手机

使用场景 - 数据库调试：访问手机 App 内置的数据库查看器（如 DebugDB 等）。 - Webview 远程调试：通过电脑浏览器调试手机上的网页。 - App 内部服务：App 内部开启了轻量级 HTTP/WebSocket Server 供外部调用。

示例 假设手机 App 在 8080 端口开启了一个服务，你想在电脑上访问它： bash # 将电脑的 9000 端口转发到手机的 8080 端口 adb forward tcp:9000 tcp:8080

结果： 在电脑浏览器访问 http://localhost:9000 即可看到手机上的内容。

# 7.1.2 adb reverse：手机访问电脑

使用场景

  • 本地后端联调：电脑正在开发 API 接口（如 Node.js/Python 服务），手机 App 需要请求这些接口。
  • 前端开发预览：手机访问电脑上 npm run dev 启动的 H5 页面。
  • 物理机联调：手机和电脑即便不在同一局域网，只要插线就能直接通信。

示例 假设电脑在 9999 端口开启了开发服务，你想在手机上预览：

# 将手机的 9999 端口反向代理到电脑的 9999 端口
adb reverse tcp:9999 tcp:9999
1
2

结果： 在手机端访问 http://localhost:9999 即可访问电脑服务。

# 7.1.3 常用管理命令

建议将这些指令集成到 Shell 脚本或常用工具流中：

功能 命令
查看所有正向转发 adb forward --list
查看所有反向代理 adb reverse --list
删除特定正向转发 adb forward --remove tcp:<local_port>
删除特定反向代理 adb reverse --remove tcp:<remote_port>
清空所有规则 adb forward --remove-all / adb reverse --remove-all

# 7.1.4 注意事项

  1. 监听地址：电脑端的服务建议监听 127.0.0.1。
  2. 系统要求：adb reverse 需要 Android 5.0 (API 21) 及以上版本。
  3. 多设备：如果连接了多台设备，需通过 -s <serial_no> 指定设备。
  4. 稳定性：USB 线断开连接后，转发规则会自动失效，重连后需重新设置。

#!/bin/bash
# 压力测试脚本

PACKAGE_NAME="com.example.app"
TEST_DURATION=300  # 5分钟
INTERVAL=1         # 1秒间隔

echo "开始压力测试..."

# 启动应用
adb shell am start -n "$PACKAGE_NAME/.MainActivity"
sleep 3

# 记录开始时间
START_TIME=$(date +%s)

# 执行压力测试
while [ $(($(date +%s) - START_TIME)) -lt $TEST_DURATION ]; do
    # 随机点击屏幕
    X=$((RANDOM % 1000))
    Y=$((RANDOM % 2000))
    adb shell input tap $X $Y
    
    # 随机按键
    KEYCODE=$((RANDOM % 100))
    adb shell input keyevent $KEYCODE
    
    # 随机滑动
    X1=$((RANDOM % 1000))
    Y1=$((RANDOM % 2000))
    X2=$((RANDOM % 1000))
    Y2=$((RANDOM % 2000))
    adb shell input swipe $X1 $Y1 $X2 $Y2
    
    sleep $INTERVAL
done

echo "压力测试完成"

# 问题解决记录

# 查找应用中的png缓存，从大到小排序

adb shell "run-as <package-name> find . -type f -name '*.png' -exec ls -lh {} +" | awk '{print $5, $NF}' | sort -rh > <output_path>
1

命令分解说明：

  1. ls -lh {} +:
    • 在手机端列出文件的详细信息。+ 号表示将多个搜索结果一次性传给 ls，比 ; 效率高得多。
    • -h: Human-readable
    • 输出格式通常为：-rw------- 1 u0_a123 u0_a123 12345 2026-04-27 10:42 ./path/to/file.png
  2. awk '{print $5, $NF}':
    • $5: 提取第五列，即文件字节大小 (bytes)。
    • $NF: 提取最后一列，即文件路径。
    • 这一步是为了过滤掉权限、所有者等无关信息，只保留“大小”和“路径”。
  3. sort -rh:
    • 在 Mac 端进行排序。
    • -r: 逆序（Reverse），让最大的文件排在最前面。
    • -h: 以人类可读格式排序（如果你之前的 ls 带了 -h，这个很有用；如果不带，加这个参数也更稳健）。

# 常见错误及解决方案

错误信息 可能原因 解决方案
device not found 设备未连接或驱动问题 检查USB连接，重启ADB服务
insufficient permissions 权限不足 使用sudo或检查设备权限

timeout 网络连接问题 检查网络设置，使用USB连接

# 性能优化建议

  1. 使用USB连接: 无线连接可能不稳定，建议使用USB连接进行调试

  3. 日志过滤: 使用精确的过滤条件，减少不必要的数据传输
