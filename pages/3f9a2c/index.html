# 🤔 iOS 生态与核心概念

iOS 是 Apple 的移动操作系统，与 Android 开放生态不同，iOS 是封闭生态闭环：IDE（Xcode）、语言（Swift/OC）、框架、分发（App Store）、签名体系全部由 Apple 主导。

  • 系统分层：应用层 → Cocoa Touch（UIKit/SwiftUI）→ Core Services（Foundation/网络）→ Core OS（内核）
  • 语言双轨：新代码 Swift，老工程 OC；可混编，桥接头文件互通
  • UI 双轨：SwiftUI 声明式（类比 Compose/ArkUI），UIKit 命令式（类比 View 体系）；存量 App 以 UIKit 为主，新 App 推荐 SwiftUI
  • 签名体系：证书（身份）+ App ID + Entitlements（能力）+ Provisioning Profile（打包进 App），与 Android 的 APK 签名模型差异极大

# Auto Layout 与 SnapKit

代码写 Auto Layout 原生 API 冗长，SnapKit 是事实标准的布局 DSL 库：链式调用、类型安全（非法约束编译期报错）、支持相对约束，让代码布局接近自然语言：

view.snp.makeConstraints { make in
    make.center.equalToSuperview()
    make.width.height.equalTo(100)
}

# 🔄 生命周期与架构模式

# App 生命周期

  • UIKit：AppDelegate（旧，全局事件）→ iOS 13+ 拆出 SceneDelegate（前台/后台激活等场景事件）：didFinishLaunching → sceneDidBecomeActive ↔ sceneWillResignActive → sceneDidEnterBackground
  • SwiftUI：@main App 协议 + .scenePhase（.active/.inactive/.background）观察

# ViewController 生命周期（面试必考）

init → loadView → viewDidLoad → viewWillAppear → viewDidAppear
      → viewWillDisappear → viewDidDisappear → deinit
1
2
  • viewDidLoad：只执行一次，做一次性初始化（加子视图、网络请求）
  • viewWillAppear/Appear：每次进入屏幕都执行，刷新数据
  • deinit：释放回调，没走说明有循环引用

# 架构模式

模式 结构 适用
MVC（Apple 官方） View+Controller 耦合在 VC 里，易成 Massive VC 小页面、老代码
MVVM ViewModel 持有状态与逻辑，View 订阅渲染 主流，配 SwiftUI/Combine 更顺
MVC+MVVM 混合 VC 管导航生命周期，VM 管数据逻辑 存量工程渐进重构

# ⚡ 并发编程

三代演进：Thread（几乎不用）→ GCD/Operation（存量主流）→ async/await（现代推荐）。

  • 主线程更新 UI 是铁律：耗时操作丢 DispatchQueue.global()，回 DispatchQueue.main 更新
  • GCD 核心：串行/并发队列 + 同步/异步派发，任务以闭包提交，DispatchGroup 做协同等待
  • 新代码用 async/await + @MainActor，可读性和安全性都更好

GCD 实战、闭包循环引用（[weak self]）、Timer 泄漏等高频坑见 swift。

# 🔍 调试与测试

  • 断点：普通/条件断点、Exception Breakpoint 抓崩溃；LLDB 常用 po（打印对象）、p（打印值）、expr（运行时改值）
  • 视图调试：Xcode → Debug View Hierarchy 看视图层级（排查布局问题神器）
  • 日志：OSLog（可过滤、发布可保留）优于 print
  • 性能：Instruments → Time Profiler（CPU）/ Leaks（泄漏）/ App Launch（启动）
  • 内存：Memory Graph Debugger 查引用关系；deinit 打日志确认释放
  • 测试：XCTest 单元测试（xcodebuild test）+ UI 测试；先会写断点调试，再补测试习惯

快捷键与 Xcode 操作细节见 xcode。

# 📦 签名与分发

概念链：证书（开发者身份）+ App ID（应用标识）+ Entitlements（声明能力）+ Provisioning Profile（把前三者与设备绑定，打包进 App）。

渠道 证书类型 限制 场景
开发调试 免费/付费均可 免费 7 天过期、3 个 App ID 日常真机调试
Ad-hoc 付费 每年 100 台设备 内测分发
TestFlight 付费 经 App Store Connect，最多 1 万人 正式内测（推荐）
App Store 付费 需审核 正式发布
企业签 $299 企业证书 理论仅内部分发 不上架分发（风险自担）

上架流程：xcodebuild archive 归档 → exportArchive 导出 ipa → App Store Connect 上传 → TestFlight 内测 → 提审。

# 🧠 底层原理指引

  • OC runtime 消息机制：方法调用推迟到运行时（objc_msgSend），支持动态添加/交换方法（Method Swizzling）——详见 ios_runtime
  • dyld 启动优化：dyld2（in-process，启动时才链接）→ dyld3（部分 out-of-process，安装时预分析 Mach-O 写缓存，加快启动）——详见 ios_runtime
  • UITableView 刷新原理（数据源驱动）——详见 ios_runtime
