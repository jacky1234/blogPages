HarmonyOS 鸿蒙开发完整指南

# 🚀 HarmonyOS 鸿蒙开发完整指南

适合人群：移动开发工程师、前端开发者、对鸿蒙生态感兴趣的技术人员
学习时间：2-3个月
前置知识：JavaScript/TypeScript基础、移动开发概念

HarmonyOS（鸿蒙操作系统）是华为开发的分布式操作系统，旨在为不同设备提供统一的操作系统体验。本指南将带你从零开始学习鸿蒙应用开发。

# 📚 你将学到什么

  1. HarmonyOS 基础概念 - 理解鸿蒙生态和架构
  2. ArkTS 语言 - 掌握鸿蒙开发语言
  3. ArkUI 框架 - 学会构建用户界面
  4. 开发工具链 - 熟练使用 DevEco Studio
  5. 实际项目开发 - 完成完整的应用开发

# 🎯 学习路径建议

graph TD A[环境搭建] --> B[ArkTS基础] B --> C[ArkUI组件] C --> D[状态管理] D --> E[网络与数据] E --> F[设备能力] F --> G[性能优化] G --> H[项目实战]

# 🤖 什么是 HarmonyOS？

HarmonyOS 是华为开发的分布式操作系统，具有以下特点：

  • 分布式架构：支持多设备协同工作
  • 统一开发：一套代码，多端运行
  • 高性能：优化的渲染引擎和内存管理
  • 安全可靠：企业级安全特性

# 核心概念

  • ArkTS：基于 TypeScript 的鸿蒙开发语言
  • ArkUI：声明式 UI 开发框架
  • Ability：应用的基本组成单元
  • HAP：HarmonyOS Ability Package，应用包格式

# 🛠️ 开发环境搭建

# 1. DevEco Studio 安装

下载地址：华为开发者官网 (opens new window)

系统要求：

  • Windows 10/11 (64位)
  • macOS 10.15 或更高版本
  • 内存：8GB 以上
  • 硬盘：10GB 以上可用空间

安装步骤：

  1. 下载 DevEco Studio 安装包
  2. 运行安装程序，按提示完成安装
  3. 首次启动时配置 SDK 路径
  4. 安装鸿蒙 SDK 和工具链

# 2. SDK 配置

# 设置环境变量（hdc 在 SDK toolchains；hvigor/ohpm 依赖 DevEco 自带 node）
export DEVECO=/Applications/DevEco-Studio.app/Contents
export NODE_HOME=$DEVECO/tools/node
export PATH=$DEVECO/tools/node/bin:$DEVECO/tools/hvigor/bin:$DEVECO/tools/ohpm/bin:$DEVECO/sdk/default/openharmony/toolchains:$PATH

# 验证安装
hdc -v               # hdc 版本
hvigorw --version    # hvigor 版本
ohpm -v              # ohpm 版本

# 3. 模拟器配置

创建模拟器：

  1. 打开 DevEco Studio
  2. 选择 Tools → Device Manager
  3. 点击 Create Device
  4. 选择设备类型和系统版本
  5. 下载并启动模拟器

模拟器类型：

  • Phone：手机模拟器
  • Tablet：平板模拟器
  • TV：智慧屏模拟器
  • Wearable：智能手表模拟器

# 4. 真机调试配置

开发者选项开启：

  1. 设置 → 关于手机 → 版本号（连续点击7次）
  2. 返回设置 → 系统和更新 → 开发者选项
  3. 开启"USB调试"和"仅充电模式下允许ADB调试"

连接调试：

# 查看连接的设备
hdc list targets

# 进入设备shell
hdc shell

# 安装应用
hdc install -p your_app.hap

# 5. ohpm 包管理器

ohpm（OpenHarmony Package Manager）是鸿蒙生态的包管理工具，类似于 npm，管理工程的三方库依赖（oh-package.json5 → oh_modules）。随 DevEco Studio 发布（位于 tools/ohpm/bin），不要用 npm 安装，配置好 PATH 即可（见上方 SDK 配置）。

ohpm install                 # 最常用：安装全部依赖
1

📖 ohpm 完整速查手册：ohpm —— 全部 19 个命令详解、oh-package.json5 工程配置（含 overrides 依赖统一）、registry/缓存管理、发布流程（publish_id + SSH key 认证）、npm↔ohpm 对照表与实测踩坑。

# 目录组织原则

  • 模块化设计：按功能划分模块，每个模块独立开发
  • 资源分离：应用级资源与模块级资源分离管理
  • 组件复用：共享组件放在shared模块中
  • 测试覆盖：每个模块包含对应的测试代码
  • 配置集中：配置文件统一管理，便于维护

# 📝 ArkTS 语言基础

ArkTS 是鸿蒙生态的编程语言，基于 TypeScript 扩展（声明式 UI、并发增强），同时施加更严格的类型约束（禁用 any、对象字面量须有明确类型等）。

📖 ArkTS 完整速查手册：arkts —— 基础语法、V1/V2 状态装饰器对照（@State/@Prop/@Link 与 @ObservedV2/@Trace/@Computed 等）、组件与页面生命周期区分、$$ 双向绑定、事件覆盖式注册、手势与常见坑速查。

# 1. hdc — 设备调试连接器

鸿蒙版 adb，能力域覆盖：设备连接、应用管理（bm/aa）、文件传输、日志 hilog、系统服务转储 hidumper、内存观测、输入注入（uinput/uitest）、端口转发、截屏。

📖 完整速查手册：hdc（含 hdc↔adb 对照表与实战踩坑配方）

# 2. ohpm — 包管理器（≈ npm）

管理工程三方库依赖（oh-package.json5 → oh_modules），与 hdc（设备侧）职责完全不同，两者互不包含、都需要。

📖 完整速查手册：ohpm（19 个命令全解、oh-package.json5 结构、发布流程、npm 对照表与踩坑）

# 3. hvigor — 构建工具（≈ gradle）

hvigor 是鸿蒙唯一的构建系统（无独立的 "ArkTS 编译器/打包工具" CLI——ArkTS 编译、打包都是 hvigor 任务）。

  • 启动入口：项目根目录 hvigorw wrapper，或全局 tools/hvigor/bin/hvigorw（实测版本 6.22.3）
  • 工程配置：hvigor/hvigor-config.json5（modelVersion、构建插件如 router/efix、daemon/并行/增量开关）
  • 真实构建产物（实测工程）：entry/build/default/outputs/default/entry-default-signed.hap、-unsigned.hap、mapping/、pack.info

hvigorw assembleApp                                   # 构建 App 包（上架，多 HAP 聚合）
hvigorw clean
hvigorw tasks                                         # 列出全部任务

# 4. 签名（无独立 signer CLI）

真实方式只有两条路：

  • IDE 自动签名：File → Project Structure → Signing Configs，勾选 Automatically generate signature（调试证书自动生成）
  • 工程配置：build-profile.json5 的 signingConfigs（证书/Profile 文件路径 + 密钥），CI 构建时 hvigorw 据此打出 -signed.hap

# 6. Native（NDK）

sdk/default/openharmony/native/ 下提供完整交叉编译链：

  • llvm/bin/aarch64-unknown-linux-ohos-clang（arm64）、armv7-unknown-linux-ohos-clang（arm32）

IDE 的 Native 模板会自动接管 cmake/clang 配置，无需手动调用。

# 7. 测试

  • hypium：官方单测框架（oh-package.json5 的 devDependencies 引入 @ohos/hypium），测试代码在 src/ohosTest/
  • aa test：设备端执行用例（hdc shell aa test -b <bundle> ...）
  • uitest：UI 自动化注入与布局检查（设备端工具，见 hdc §8）
  • UxTestService：IDE 内置 UX 检测服务（tools/UxTestService，Python 实现）

# 8. 性能分析

  • IDE Profiler（内置）：实时内存/CPU/渲染帧率分析，底层服务 tools/profiler/dic_server
  • 设备端：hiperf（CPU 剖析）、hidumper --mem（PSS）、hidumper --mem-jsheap（ArkTS 堆快照/泄漏对象）→ 见 hdc §6/§7

# 9. 模拟器与预览

  • Emulator：真实二进制位于 tools/emulator/Emulator（Qt 程序），由 IDE 的 Device Manager（Tools → Device Manager）创建和启动，日常无需手动调用
  • Previewer：IDE 内置双栏预览（SDK 内 previewer 目录），改代码即时看 UI

  • Code Linter：IDE 内置（plugins/codelinter），ArkTS 语法与规范检查，无独立 CLI

// pages/Index.ets
import { Todo } from '../models/Todo'
import { TodoItem } from '../components/TodoItem'
import { Storage } from '../utils/Storage'

@Entry
@Component
struct Index {
  @State todos: Todo[] = []
  @State newTodoTitle: string = ""

  aboutToAppear() {
    Storage.init(getContext(this))    // 初始化 Preferences 实例（需页面上下文）
    this.loadTodos()
  }

  private loadTodos() {
    this.todos = Storage.getTodos()
  }

  private addTodo() {
    if (this.newTodoTitle.trim()) {
      const todo = new Todo(this.newTodoTitle.trim())
      this.todos.push(todo)
      this.newTodoTitle = ""
      Storage.saveTodos(this.todos)
    }
  }

  private toggleTodo(id: string) {
    const todo = this.todos.find(t => t.id === id)
    if (todo) {
      todo.completed = !todo.completed
      Storage.saveTodos(this.todos)
    }
  }

  private deleteTodo(id: string) {
    this.todos = this.todos.filter(t => t.id !== id)
    Storage.saveTodos(this.todos)
  }

  build() {
    Column({ space: 20 }) {
      // 标题
      Text("待办事项")
        .fontSize(24)
        .fontWeight(FontWeight.Bold)
        .margin({ top: 20 })

      // 添加待办输入框
      Row({ space: 10 }) {
        TextInput({ placeholder: "输入待办事项" })
          .layoutWeight(1)
          .onChange((value: string) => {
            this.newTodoTitle = value
          })
          .onSubmit(() => {
            this.addTodo()
          })

        Button("添加")
          .onClick(() => {
            this.addTodo()
          })
      }
      .width('100%')
      .padding({ left: 20, right: 20 })

      // 待办列表
      List() {
        ForEach(this.todos, (todo: Todo) => {
          ListItem() {
            TodoItem({
              todo: todo,
              onToggle: () => this.toggleTodo(todo.id),
              onDelete: () => this.deleteTodo(todo.id)
            })
          }
        }, (todo: Todo) => todo.id)    // keyGenerator：以 id 为键，提升 diff 性能
      }
      .layoutWeight(1)
      .width('100%')
    }
    .width('100%')
    .height('100%')
    .backgroundColor('#F5F5F5')
  }
}

          type: this.todo.completed ? TextDecorationType.LineThrough : TextDecorationType.None
        })
        .fontColor(this.todo.completed ? '#999' : '#333')
        .layoutWeight(1)

      // 删除按钮
      Button("删除")
        .fontSize(12)
        .backgroundColor('#FF6B6B')
        .onClick(() => {
          this.onDelete?.()
        })
    }
    .width('100%')
    .padding(10)
    .backgroundColor('#FFF')
    .borderRadius(8)
    .margin({ bottom: 5 })
  }
}

# 存储工具

// utils/Storage.ets
import { preferences } from '@kit.ArkData'
import { Context } from '@kit.AbilityKit'
import { Todo } from '../models/Todo'

// JSON 反序列化后的原始形状（Date 经 stringify 变为 ISO 字符串）
interface TodoJson {
  id: string
  title: string
  completed: boolean
  createdAt: string
}

export class Storage {
  // preferences 模块没有模块级 putSync/getSync，
  // 必须先 getPreferencesSync(context, options) 拿到实例再操作
  private static pref: preferences.Preferences | undefined = undefined

  static init(context: Context): void {
    this.pref = preferences.getPreferencesSync(context, { name: 'todo_store' })
  }

  static saveTodos(todos: Todo[]): void {
    try {
      this.pref?.putSync('todos', JSON.stringify(todos))
      this.pref?.flush()    // putSync 只写内存缓存，flush 才落盘
    } catch (error) {
      console.error('保存待办事项失败:', error)
    }
  }

  static getTodos(): Todo[] {
    try {
      const data = this.pref?.getSync('todos', '[]') as string
      const list = JSON.parse(data) as TodoJson[]
      return list.map((item: TodoJson): Todo => {
        const t = new Todo(item.title)
        t.id = item.id
        t.completed = item.completed
        t.createdAt = new Date(item.createdAt)
        return t
      })
    } catch (error) {
      console.error('加载待办事项失败:', error)
      return []
    }
  }
}

# Q2: 如何处理网络请求？

A: 网络请求示例：

import http from '@ohos.net.http'

async function fetchData() {
  const httpRequest = http.createHttp()
  try {
    const response = await httpRequest.request('https://api.example.com/data', {
      method: http.RequestMethod.GET,
      header: {
        'Content-Type': 'application/json'
      }
    })
    return JSON.parse(response.result as string)
  } catch (error) {
    console.error('网络请求失败:', error)
  } finally {
    httpRequest.destroy()
  }
}
